# 프롬프트: 블로그 원고 작성

## 목적
선정된 주제로 희림 블로그에 올릴 **완성 원고 초안**을 한국어로 작성한다.

## 필요한 입력
- 주제 (제목안 또는 주제선정 문서의 항목)
- 참고 이슈 링크 (주간 다이제스트/노션에서)
- 분량 (기본: 1,500~2,500자)
- 강조할 희림 관점 (선택)

## 절차
1. `reference/heerim-brand.md`(톤·전문 영역), `reference/audience.md`를 읽는다.
   톤은 **중립 해설체, 자사 언급 최소**가 원칙.
2. 참고 링크의 사실관계를 다시 확인한다. 불확실하면 원고에서 단정하지 않는다.
3. `templates/blog-post.md` 구조로 작성:
   - 후킹 도입 (독자가 왜 읽어야 하는지) → 배경/맥락 → 핵심 내용(소제목 3~5) → 건축적 해석 →
     실무 관점·심화 해석(설계·CM·감리 등, 희림 사례는 필요할 때만 1~2회) → 정리 + 독자에게 남기는 질문
4. 전문 용어는 처음 등장 시 한 줄로 풀어준다. 문장은 간결하게.
5. 팩트마다 출처를 각주 또는 본문 링크로. 이미지가 필요한 위치에 `[이미지: 설명]` 표시.
6. 하단에 메타: 추천 제목 3개 / 메타 디스크립션(120자) / 해시태그·키워드 / 참고 출처 목록.
7. `outputs/YYYY-MM-DD-블로그-<주제슬러그>.md`로 저장.
8. **노션 `콘텐츠 원고` DB에 1행 추가** (data_source_id는 `reference/notion-setup.local.md` 참조):
   - 제목 = 확정 제목 / 유형 = "블로그" / 상태 = "초안" / 작성일 = 오늘 / 로컬 파일 = outputs 경로
   - 대상 이슈 = 참고한 `건축 이슈 수집` 행을 relation으로 연결
   - 원고 본문(마크다운)을 그 행의 페이지 본문에 넣는다 (한국어는 이스케이프 없이 그대로)
   - 참고한 이슈 행의 상태를 "제작완료"로 변경
   - 연동 안 되면 이 단계는 건너뛰고 사용자에게 알림

## 출력 형태
- 템플릿: `templates/blog-post.md`
- 저장 위치: `outputs/YYYY-MM-DD-블로그-<주제슬러그>.md` + 노션 `콘텐츠 원고` DB

## 품질 체크리스트
- [ ] 도입 3문장 안에 읽을 이유가 제시된다
- [ ] 모든 사실 주장에 출처가 있다
- [ ] 희림 언급이 1~2회 또는 없음, 억지 연결이 아니다
- [ ] 전문 용어가 풀이돼 일반대중도 따라갈 수 있다
- [ ] 브랜드 톤(heerim-brand.md)과 일치한다
- [ ] 표절 없이 자체 문장으로 재구성됐다
- [ ] 이미지 삽입 위치가 표시됐다
- [ ] 노션 `콘텐츠 원고` DB에 행이 생기고 본문이 들어갔다 (연동 시)
